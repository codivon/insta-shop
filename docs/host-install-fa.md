# 🚀 راهنمای کامل نصب InstaShop روی هاست اشتراکی (cPanel / دایرکت‌ادمین)

این راهنما برای نصب روی هاست‌های اشتراکی ایرانی (cPanel یا مشابه) نوشته شده است و **به SSH، ترمینال و Composer نیازی ندارد**.

---

## ✋ اگر با خطای زیر مواجه شده‌اید (سؤال پرتکرار)

```
Warning: require(.../vendor/autoload.php): Failed to open stream: No such file or directory
```

علت: پوشه `vendor` جزو فایل‌های git نبود و با clone یا آپلود دستی سورس منتقل نمی‌شد.

**راه‌حل (دو راه):**
1. از [صفحه Releases ریپو](https://github.com/codivon/insta-shop/releases) پکیج آماده‌ی هاست را دانلود کنید — مثلاً `instashop-v0.7.0-host.zip`
2. یا از نسخه‌ای که شامل کامیت «track vendor» است به بعد، **پوشه `vendor` داخل خود ریپو هست** → از گیت‌هاب «Download ZIP» بگیرید یا با cPanel Git کلون کنید — vendor همراهش هست

---

## ✋ اگر هنگام نصب خطای دیتابیس گرفتید (سؤال پرتکرار دوم)

```
SQLSTATE[42000]: ... 1071 Specified key was too long; max key length is 1000 bytes
```

علت: برخی هاست‌ها جدول‌ها را با موتور **MyISAM** (سقف ایندکس ۱۰۰۰ بایت) یا InnoDB قدیمی (۷۶۷ بایت) می‌سازند؛ ایندکس ستون‌های `varchar(255)` با یونیکد utf8mb4 حدود ۱۰۲۰ بایت می‌خواهد و خطای بالا را می‌دهد.

این مشکل از نسخه **v0.7.2** به‌طور کامل حل شده است:
- طول پیش‌فرض ستون‌های ایندکس‌دار به ۱۹۱ کاهش یافت (۷۶۴ بایت — روی همه موتورها جا می‌شود)
- جداول به‌صورت پیش‌فرض با موتور **InnoDB** ساخته می‌شوند (حذف آبشاری و کلیدهای خارجی هم واقعاً کار می‌کنند؛ در صورت نیاز استثنایی در `.env` مقدار `DB_ENGINE=MyISAM` بگذارید)
- اگر نصبِ نیمه‌کاره‌ای مانده باشد (مثلاً جدول `users` بدون ایندکس ساخته شده)، ویزارد هنگام اجرای مجدد **خودش جدول‌های نیمه‌کاره را پاک و از نو می‌سازد** — فقط فایل‌ها را به‌روز کنید (مرحله ۵) و دوباره `/install` را باز کنید

---

| نیاز | مقدار | توضیح |
|---|---|---|
| PHP | **۸.۳ یا بالاتر** | از MultiPHP Manager در cPanel تنظیم کنید |
| افزونه‌های PHP | `pdo_mysql`, `mbstring`, `openssl`, `fileinfo`, `ctype`, `json`, `curl`, `dom` | نصب‌کننده هنگام نصب همه را بررسی می‌کند |
| دیتابیس | MySQL 8+ یا MariaDB 10.4+ | در مرحله «MySQL Databases» cPanel می‌سازید |
| فضای دیسک | ~۳۰۰ مگابایت | سورس + vendor + دیتابیس و فایل‌ها |

---

## مرحله ۱ — ساخت دیتابیس در cPanel

1. وارد cPanel شوید → بخش **MySQL® Databases**
2. در *Create New Database* یک نام بسازید (مثلاً `user_instashop`) → Create
3. در *MySQL Users → Add New User* یک کاربر بسازید و رمز قوی بگذارید
4. در *Add User To Database* کاربر را به دیتابیس اضافه کنید و تیک **ALL PRIVILEGES** را بزنید
5. سه مقدار زیر را یادداشت کنید:
   - **نام دیتابیس** (مثلاً `owqdlxcv_instashop`)
   - **نام کاربری** دیتابیس
   - **رمز عبور** کاربر

> 💡 نام میزبان دیتابیس روی اکثر هاست‌ها `localhost` است و پورت `3306`.

---

## مرحله ۲ — آپلود پکیج

1. پکیج هاست را از [Releases](https://github.com/codivon/insta-shop/releases) دانلود کنید یا ZIP ریپو (با vendor) را بگیرید
2. در cPanel → **File Manager** به پوشه‌ای بروید که دامنه/ساب‌دامین شما به آن اشاره می‌کند:
   - اگر دامنه مستقیم به پوشه پروژه اشاره می‌کند (مثل `/home/USER/repositories/insta-shop`) → فایل‌ها را در همان پوشه Extract کنید
   - اگر `public_html` ریشه دامنه است → پکیج را داخل یک پوشه Extract کنید و **ساب‌دامین** را به همان پوشه متصل کنید (بهترین روش) یا `public_html/.htaccess` را طوری تنظیم کنید که به پوشه برود
3. فایل zip را در File Manager انتخاب → **Extract**
4. مطمئن شوید `index.php` و `.htaccess` در ریشه پوشه دامنه هستند

> فایل `.htaccess` ریشه به‌صورت خودکار همه درخواست‌ها را به `public/` می‌فرستد و فایل‌های حساس (`.env`، `.git` و…) را می‌بندد. لازم نیست دامنه را به `public` اشاره دهید.

---

## مرحله ۳ — دسترسی‌های نوشتن

در File Manager روی پوشه‌های زیر راست‌کلیک → **Change Permissions** → مقدار **775** (یا 755):

```
storage/          (و همه زیرپوشه‌ها)
bootstrap/cache/
```

اگر File Manager اجازه بازگشتی (recursive) داد، برای `storage` گزینه *Recurse into subdirectories* را هم بزنید.

---

## مرحله ۴ — نصب با ویزارد وب

1. آدرس سایت را در مرورگر باز کنید (مثلاً `https://example.com`)
2. به‌صورت خودکار به `/install` هدایت می‌شوید
3. مراحل ویزارد:
   - **خوش‌آمد** → شروع
   - **بررسی سرور** → همه موارد سبز باشند (اگر افزونه‌ای قرمز بود از پشتیبانی هاست بخواهید فعالش کند؛ موارد کهربایی اختیاری‌اند)
   - **دیتابیس** → مقادیر مرحله ۱ را وارد کنید → دکمه «بررسی اتصال و ادامه»
   - **نصب** → صبر کنید؛ مایگریشن‌ها و سیدرها **یکی‌یکی اجرا می‌شوند** و درصد پیشرفت بالا می‌رود (با هر تعداد جدول هم کرش نمی‌کند؛ اگر وسط راه قطع شد، با دکمه «تلاش مجدد» یا رفرش صفحه از همان‌جا ادامه می‌دهد)
   - **پایان** → خلاصه نصب نمایش داده می‌شود 🔒
4. پس از پایان، نصب‌کننده **قفل می‌شود** و دیگر کسی به `/install` دسترسی ندارد

> پس از نصب می‌توانید پنل‌ها را باز کنید: `/admin` (مدیریت)، `/seller` (فروشنده)، `/shop` (فروشگاه)

---

## مرحله ۵ — نصب مجدد یا جابه‌جایی هاست

برای شروع دوباره‌ی نصب (مثلاً روی هاست دیگر یا با دیتابیس دیگر، یا پس از به‌روزرسانی فایل‌ها برای گرفتن فیکس‌ها):

1. فایل‌های جدید را جایگزین کنید (با cPanel Git → pull، یا Download ZIP از ریپو/Releases و Extract)
2. فایل `.env` در ریشه پروژه را حذف کنید
3. فایل `storage/app/install.lock` را حذف کنید
4. آدرس سایت را باز کنید → ویزارد دوباره اجرا می‌شود (مایگریشن‌های قبلی به‌صورت خودکار skip می‌شوند؛ جدول‌های نیمه‌کاره هم خودکار پاک و از نو ساخته می‌شوند)

## 🔧 رفع اشکال

| مشکل | راه‌حل |
|---|---|
| خطای `vendor/autoload.php not found` | پکیج Releases را نصب کنید یا ZIP نسخه‌ای از ریپو که vendor دارد را بگیرید؛ یا `composer install --no-dev` اجرا کنید |
| خطای 500 سفید | معمولاً دسترسی `storage` است — مرحله ۳ را دقیق انجام دهید؛ اگر PHP قدیمی‌تر از 8.3 است، از MultiPHP Manager ارتقا دهید |
| «توسعه PHP نصب نیست» در بررسی سرور | از پشتیبانی هاست بخواهید PHP 8.3+ را برای دامنه فعال کند |
| خطای اتصال دیتابیس | نام میزبان را `localhost` بگذارید؛ نام دیتابیس/کاربر در cPanel معمولاً پیشوندِ یوزرنیمِ هاست دارد (کامل بنویسید) |
| خطای `1071 Specified key was too long` هنگام نصب | از v0.7.2 حل شده — فایل‌ها را به‌روز کنید (مرحله ۵) و دوباره نصب کنید؛ نصب نیمه‌کاره هم خودکار ترمیم می‌شود |
| صفحات بدون استایل | فایل `public/build` نباید حذف شده باشد؛ در پکیج آماده هست — دوباره Extract کنید |
| ارسال ایمیل/پیامک | بعد از نصب از پنل ادمین → تنظیمات، پروایدر پیامک و درگاه پرداخت را پیکربندی کنید |

---

## 🔒 نکات امنیتی پس از نصب

- نصب‌کننده پس از پایان قفل می‌شود؛ اگر خواستید مطمئن‌تر باشید، فایل `packages/` را از روی هاست حذف کنید (فقط برای نصب لازم است)
- `APP_DEBUG` در `.env` روی `false` است — برای عیب‌یابی موقتاً `true` کنید و بعد برگردانید
- بکاپ منظم از دیتابیس و پوشه `storage` بگیرید
